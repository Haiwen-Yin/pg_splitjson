# PG SplitJSON 0.3.0 release note

**English** | [简体中文](RELEASE_NOTE.zh-CN.md) · [README](README.md) · [API reference](docs/api-reference.md)

**PostgreSQL Split JSON Storage Extension (PG SplitJSON) 0.3.0** is ready for the tested PostgreSQL 18.6/Linux x86_64 source release. It is licensed under the [Apache License 2.0](LICENSE) (`Apache-2.0`), installs as `pg_splitjson`, and exposes SQL in `splitjson`.

0.3.0 keeps the 0.2.0 hot/cold view contract and adds caller-aware RLS, id-only HASH/RANGE storage, revision epochs, conditional writes, native upsert, RFC 6902 Patch, RFC 7396 Merge Patch, typed indexes/ranges, snapshot portability, online WAL layout migration and same-layout native logical replication with fenced takeover. Existing 0.1.0 and 0.2.0 SQL, historical evidence and the 0.2.0 archive remain preserved.

## Verification

The final PG18.6 lab passed the frozen regression/upgrade suite, RLS and COPY, planner/index/array checks, one-write and TOAST checks, backup/restore, crash/PITR/physical promotion and workload tests. A separate online lab passed atomic snapshot/WAL replay, unchanged-TOAST reconstruction, real process/PG crash recovery, slot-loss detection, final fencing and abort. A two-PGDATA lab passed native publication/subscription, RLS/ACL separation, worker pause/resume/restart, partition-root replication and verified takeover. Evidence is summarized in [validation-030](docs/validation-030.md).

## Boundaries

The source package targets PostgreSQL 18.6/Linux x86_64; other minors and architectures require separate validation. Native view `ON CONFLICT`, arbitrary transparent view-DML translation, cross-layout automatic logical reassembly, multi-primary replication, non-id partition keys and Oracle-style general duality views are outside scope. General duality views are not a future milestone. `pg_dump -t` on a business view does not include private storage dependencies.

The release archive is generated by `scripts/package-release.py` into `build_output/0.3.0/` and contains only the explicit source, SQL, scripts, tests and paired public docs. It contains no Git data, local labs, databases, dumps, binaries or JSONL exports. No tag or GitHub upload is performed here.
